API

The functions you call. Each takes the path of a replibuild.toml, or of the folder that holds one, and does nothing when its inputs have not changed.

Check the machine

RepliBuild.check_environment — Function
check_environment(; verbose=true, throw_on_error=false) -> ToolchainStatus

Run environment diagnostics to verify LLVM 21+, MLIR, CMake, and other toolchain requirements.

Prints a colorful report showing which tools are found, their versions, and installation instructions for anything missing. Use throw_on_error=true to abort on missing requirements.

Example

status = RepliBuild.check_environment()
status.ready          # true if Tier 3 (ccall) builds will work
status.tier2_ready    # true if MLIR JIT tier is also available
source

status.ready is true when C libraries can be wrapped, and status.tier2_ready when C++ libraries can. Set up explains the report.

Build and wrap

toml = RepliBuild.discover("path/to/project")   # write replibuild.toml
RepliBuild.build(toml)                           # compile the library
RepliBuild.wrap(toml)                            # write julia/<Name>.jl
  • discover(path; build = true, wrap = true) does all three and registers the result.
  • discover keeps an existing replibuild.toml. discover(path; force = true) rewrites it, keeping only some keys.
  • build(toml; clean = true) deletes everything built first. Downloaded sources are kept.
  • clean(toml) keeps downloaded sources too. At the Julia prompt it asks whether to delete them; clean(toml; deps = true) deletes them without asking, and deps = false keeps them without asking.
RepliBuild.discover — Function
discover(target_dir="."; force=false, build=false, wrap=false) -> String

Scan a C or C++ project and generate its replibuild.toml. In a directory that holds a Cargo.toml and no replibuild.toml yet, the project is that Rust crate: cargo is asked what it is, and the file names it under [rust].

This is the entry point for new projects. Run this first to set up RepliBuild.

An existing replibuild.toml is kept, not rescanned, unless force=true; build and wrap still run against it. With build=true, wrap=true it builds and wraps the project where it lives, then registers it (register): the build is vendored system-wide and added to the Julia environment.

Arguments

  • target_dir: Project directory to scan (default: current directory)
  • force: Force rediscovery even if replibuild.toml exists (default: false)
  • build: Automatically run build() after discovery (default: false)
  • wrap: Automatically run wrap() after build (requires build=true, default: false)

Returns

Path to the replibuild.toml file

Workflow

Basic workflow (step-by-step):

# 1. Discover and create config
toml_path = RepliBuild.discover()

# 2. Build the library
RepliBuild.build(toml_path)

# 3. Generate Julia wrappers
RepliBuild.wrap(toml_path)

Chained workflow (automated):

# Discover → Build → Wrap (all at once)
toml_path = RepliBuild.discover(build=true, wrap=true)

# Or just discover and build
toml_path = RepliBuild.discover(build=true)

Examples

# Discover current directory
RepliBuild.discover()

# Discover another directory
RepliBuild.discover("path/to/cpp/project")

# Force regenerate config
RepliBuild.discover(force=true)

# Full automated pipeline
RepliBuild.discover(build=true, wrap=true)
source
RepliBuild.build — Function
build(toml_path="replibuild.toml"; clean=false)

Compile C++ project → library (.so/.dylib/.dll)

What it does:

  1. Compiles your C++ code to LLVM IR
  2. Links and optimizes IR
  3. Generates library file
  4. Extracts metadata (DWARF + symbols) for wrapping

What it does NOT do:

  • Does NOT generate Julia wrappers (use wrap() for that)

Arguments

  • toml_path: Path to replibuild.toml configuration file (default: "replibuild.toml")
  • clean: delete what the last build wrote before building, keeping the sources the project downloaded (default: false)

Returns

Library path (String). For a [graph] project, the output directory that holds every library of the graph (see GraphMode).

Examples

# Build using replibuild.toml in current directory
RepliBuild.build()

# Build with specific config file
RepliBuild.build("path/to/replibuild.toml")

# Clean build
RepliBuild.build(clean=true)

# Then generate Julia wrappers:
RepliBuild.wrap("replibuild.toml")
source
RepliBuild.wrap — Function
wrap(toml_path="replibuild.toml"; headers=String[])

Generate Julia wrapper from compiled library

What it does:

  1. Loads metadata from build (DWARF + symbols)
  2. Generates Julia module with ccall wrappers
  3. Creates type definitions from C++ structs
  4. With [compile] aot_thunks = true (C++), compiles the thunks the wrapper binds into lib<name>_thunks.<ext> beside the library
  5. Saves to julia/ directory

Requirements:

  • Must run build() first
  • Metadata must exist in julia/compilation_metadata.json
  • AOT thunks need the JLCS dialect library and clang++, as build does for C++

Arguments

  • toml_path: Path to replibuild.toml configuration file (default: "replibuild.toml")
  • headers: C++ headers for advanced wrapping (optional)

Returns

Path to generated Julia wrapper file. For a [graph] project, the graph module <output>/<Module>.jl, which includes one wrapper per library in load order.

Examples

# Generate wrapper using replibuild.toml in current directory
RepliBuild.wrap()

# Generate wrapper with specific config file
RepliBuild.wrap("path/to/replibuild.toml")

# With headers for better type info
RepliBuild.wrap("replibuild.toml", headers=["mylib.h"])
source
RepliBuild.clean — Function
clean(toml_path="replibuild.toml"; deps=nothing)

Remove what a build wrote: build/, julia/ and the caches.

The sources a project downloaded (the git checkouts and unpacked archives under .replibuild_cache/deps/) are kept unless you say otherwise. They have not changed, and deleting them only makes the next build download them again.

Arguments

  • toml_path: Path to replibuild.toml configuration file (default: "replibuild.toml")
  • deps: what to do with the downloaded sources.
    • not given: at an interactive prompt, clean asks whether to delete them too, and keeps them on anything but y. Anywhere else (a script, a test, a notebook) it keeps them and says how to delete them.
    • deps=false: keep them, without asking. The next build checks each one against the recipe's pin instead of fetching it.
    • deps=true: delete them, without asking.

Examples

# Clean using replibuild.toml in current directory
RepliBuild.clean()

# Clean specific project
RepliBuild.clean("path/to/replibuild.toml")

# In a script: keep the downloaded sources, ask nothing
RepliBuild.clean("path/to/replibuild.toml"; deps=false)

# Delete the downloaded sources too
RepliBuild.clean("path/to/replibuild.toml"; deps=true)
source

RepliBuild.register("replibuild.toml")

Load it anywhere explains what each does.

RepliBuild.register — Function
register(toml_path::String; name="", build=true, env=:default) -> RegistryEntry

Record a project in the global registry and vendor its build, so it loads in any session by RepliBuild.use(name) and by using <Module>.

The project builds where it lives: register runs build and wrap on it (a cache hit when its build is current), copies the result to ~/.replibuild/builds/<hash>/, writes a Julia package around it in ~/.replibuild/packages/<Module>/, and adds that package to the Julia environment env:

  • :default — the @v#.# environment, which every session can load from;
  • :active — the active environment;
  • a path to an environment;
  • nothing — no environment; use still loads it.

ENV["REPLIBUILD_JULIA_ENV"] (default, active, none, or a path) changes the default. A package's own Project.toml is never changed. build=false records the project only, and use(name) builds it later. Name is inferred from [project].name if not provided. discover(path; build=true, wrap=true) ends by calling this.

source
RepliBuild.use — Function
use(name::String; force_rebuild=false, verbose=true) -> Module

Load a wrapper by local registry name. Resolves dependencies, checks environment, builds if needed, and returns the loaded Julia module.

The name must already be registered (register(toml), or discover(path; build=true, wrap=true)). There is no Hub fallback — a missing name errors.

use loads the build register vendored while the project's inputs still match it. After an edit it builds and wraps the project where it lives, vendors the new build, and loads that; a project that has moved still loads from its last vendored build. force_rebuild=true builds the project from nothing first (git dependencies are fetched again).

Call it at top level: the module is defined while your code runs, so calling into it from the function that called use needs Base.invokelatest.

Example

RepliBuild.register("path/to/replibuild.toml")   # builds in place, vendors, adds to the Julia env
M = RepliBuild.use("myproject")                  # [project].name
source

Ingest

Wraps a C library you compiled yourself with -g, without building it from source. It is experimental and does not support C++. Prefer discover, build and wrap whenever the source builds.

RepliBuild.ingest — Function
ingest(library_path; headers=String[], extra_link_libs=String[],
                     name="", project_dir=".", language=:c, build=false, wrap=false,
                     register=true) -> String

EXPERIMENTAL. Scaffold a replibuild.toml for ingest mode: wrap a pre-built .so (built by upstream's own build system) without recompiling. RepliBuild only runs DWARF metadata extraction + wrapper generation; the library must be built with -g.

Support matrix — the maintained, flagship path is the source-build pipeline (discover/build/wrap), where RepliBuild's own version-matched compilation guarantees the DWARF it consumes:

  • language = :c — works for plain-C ABIs (Tier-3 ccall only, no bitcode/thunks), but is best-effort: upstream's compiler and debug-info settings are outside RepliBuild's control, so extraction quality varies. Prefer the source build when the sources compile under one flag set.
  • language = :cpp — NOT supported. The C++ ABI surface (classes, methods, templates, virtual dispatch) requires the MLIR dialect to marshal calls and generate thunks, which only the source-build pipeline produces. Ingesting a C++ library can at best expose its extern "C" surface; the generated wrapper for the C++ API proper is unusable. If the library ships a C API variant, ingest that with language = :c instead.

This is the fallback for C libraries with elaborate build systems (autotools, CMake with code generators, configure scripts) that RepliBuild's source-build pipeline can't reproduce.

Arguments

  • library_path: path to the pre-built .so / .dylib / .dll
  • headers: header search dirs for type extraction (recommended)
  • extra_link_libs: additional -l libraries the wrapper needs at load time
  • name: project name (default: derived from library basename)
  • project_dir: where to write replibuild.toml (default: cwd)
  • language: :c or :cpp — drives wrapper generator selection
  • build: also run build() after scaffolding
  • wrap: also run wrap() (requires build=true)
  • register: with build=true, wrap=true, register the project afterwards (register), as discover does; false builds and wraps only

Registration follows discover: a bare call writes the TOML and does nothing else. With build=true, wrap=true it builds and wraps the project in project_dir, then registers it, which vendors the build to ~/.replibuild/builds/ and adds a package to a Julia environment (@v#.# unless ENV["REPLIBUILD_JULIA_ENV"] names another). A registration failure is thrown, not logged.

Returns

Path to the generated replibuild.toml.

Example

toml = RepliBuild.ingest("/usr/lib/libsqlite3.so",
                         headers=["/usr/include"],
                         name="sqlite_ingest",
                         build=true, wrap=true)
