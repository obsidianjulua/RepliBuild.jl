Changelog

The full, dated history is CHANGELOG.md in the repository. This page is what a user upgrading should know.

This manual is built from main. Pkg.add("RepliBuild") installs the newest registered release, which can be older than what is described here; pkgversion(RepliBuild) says which version you have.

After any upgrade

  • Generator fixes reach a wrapper when it is generated again. Run wrap(toml) for a wrapper you include; a wrapper written by an older RepliBuild warns when it loads. Packages loaded through use() are re-wrapped by themselves, because its cache key includes RepliBuild's version.
  • Fixes in what build extracts (the metadata) need a rebuild as well, and a build whose inputs did not change is skipped — by use() too. Run build(toml; clean=true) before wrap, or delete .replibuild_cache/project_hash and run build(toml), which keeps the compiled IR. For a registered package, call use(name; force_rebuild=true) once. The notes below say when a release has such fixes.
  • On Windows, build the JLCS dialect again: the new version lives in a new folder (Set up).

v4.6.0 (2026-11-21)

Julia 1.13 is the oldest release supported; on Julia 1.12, Pkg.add keeps installing the 4.5 releases. On Linux RepliBuild now brings its own tools and its own C++ support library, so there is much less to install, and it wraps Rust crates. After upgrading, every C project links again by itself, C++ projects should be rebuilt, and every wrapper should be generated again.

  • Rust crates. discover, build, wrap and use work on a Cargo crate as it is, with no extern "C" and no #[repr(C)]: public functions (#[inline] ones included), structs and enums, String and Vec, Box, Option, Result as a value or a thrown error, a panic as a Julia exception, trait objects, callbacks and statics. A generic function is wrapped for the types the recipe names. It needs cargo and rustc, and runs on Linux; Windows has not been run (Rust crates).

  • libJLCS is downloaded on Linux. RepliBuild's C++ support library comes ready-made, for x86-64 and AArch64, so a C++ library needs clang++ and LLVM but no MLIR packages and no build step. A library you built yourself still wins, and one built before this release must be built again: check_environment() says so. REPLIBUILD_JLCS chooses local, artifact or a path. Windows builds its own, as before.

  • The tools come with RepliBuild on Linux. readelf, nm, objdump, c++filt, git, cmake, ninja and the linker for C projects are the package's own copies, with the system's used when one cannot start. A C library needs only the C library's development files. REPLIBUILD_TOOLS=system prefers your copies, and REPLIBUILD_TOOL_<NAME> names one program. On Windows the system's copies stay first (Set up).

  • llvm-dwarfdump is no longer required on a machine that only loads a C++ wrapper: RepliBuild's own copy is used where the system has none.

  • check_environment() reports where each tool comes from, and has a Rust section.

  • The first discover of a session takes seconds. It used to compile build, wrap and register before it ran, for a minute and a half.

  • Support and versions is a new page: which releases get fixes, where RepliBuild runs, and what a version number promises.

  • Calls that were wrong, and are now right or refused. Twenty-two small libraries were wrapped and then called from Julia; what that found:

    • Loading a C++ wrapper crashed when any function took, by value, a class with a destructor. A move-only class passed by value was copied bytewise.
    • A pointer or reference to an enum was passed as the enum's value.
    • A C++ pointer parameter read whatever it was given as an address: a struct value, a Julia function, a Vector. It now refuses what C++ would not take there, with a MethodError.
    • The constructor of a class with a virtual base crashed, and some virtual methods were called statically (Dog_name(puppy) returned the base class's answer).
    • An extern "C" function in a C++ library that throws ended the process. The exception now arrives in Julia.
    • A signed bitfield read as unsigned; a char parameter refused a negative value; a SubString passed as a C string was read to its parent's end; a signed char* return came back as a String.
    • One unsigned __int128 in a library refused the whole wrap.
    • A library function named String, Cint, eval or include, or a C++ class named Bool or Integer, changed Base or broke the module. Such a name moves (String_, c_Integer), and wrap prints each move.

  • Found by rebuilding the Hub's packages before this release:

    • A C++ function written with a const number parameter (double scaled(const double x, const int n)) could return a wrong number with no error: scaled(2.5, 4) gave 0.0.
    • A struct whose members are const, returned by value, could make every call stub of its library fail to load. llama.cpp lost all its C++ calls that way.
    • A library with a header meant for one source file only, because it defines functions (fmt's format-inl.h, clipper2's clipper.export.h), did not build: the code the build adds for inline constructors and methods included that header a second time. The build now leaves such a header out, prints its name, and carries on.

    All three are in 4.5.1 as well; 4.5.2 fixes them for Julia 1.12.

  • Wrapper names and calls that change — re-wrap, and update callers:

    • C++ comparison, shift, arrow and array-new/delete operators have new names (operatorless, operatorlessless, operatorminusgreater, …). operator(), operator[] and operator, have their own names (operatorcall, operatorindex, operatorcomma) and keep the old shared one.
    • Two factory functions that take the same arguments no longer share one constructor, where one of them silently won. Each is called by name: Animal(Val(:make_animal), Cint(4)).
    • A global or a no-argument function named like its struct is name_(); name() stays the zeroed struct.
    • The constructor of an abstract class is refused, as C++ refuses it.
    • A pure virtual method is callable on a pointer the library returns.
    • C++ globals inside a namespace and public static members have accessors, named by their scope (cfg_depth()).
    • A C enum parameter takes an integer as well as the enum.
    • A String that holds a NUL byte is refused, with an ArgumentError, wherever a C function takes a const char*; it used to be cut short at the NUL. That includes a function that takes the length as well, such as lua_pushlstring(L, s, n), which used to get every byte. Pass codeunits(s) or a byte vector there.

  • Fixes in what build extracts — rebuild, then re-wrap: an array of 65536 elements or more had no size; C++ globals outside the global namespace; pure virtual methods; and the fact that lets a C++ library's extern "C" functions be called directly again. Until a C++ package is rebuilt, those functions go through call stubs, which is correct and slower.

  • Debug information can be read in-process on Linux with REPLIBUILD_DWARF=libdw. It is opt-in and gives the same answer.

v4.5.2 (2026-11-22)

For Julia 1.12: three fixes from 4.6.0, and nothing else. Updating on Julia 1.12 installs it. Each problem was confirmed on 4.5.1 first.

  • A C++ function written with a const number parameter (double scaled(const double x, const int n)) could return a wrong number with no error. It is called correctly now.
  • A struct whose members are const, passed or returned by value, could make every call stub of its library fail to load.
  • A library with a header meant for one source file only, because it defines functions (fmt's format-inl.h, clipper2's clipper.export.h), did not build. The build now leaves such a header out of the code it adds, prints its name, and carries on.
  • After updating, most wrappers need nothing. A wrapper whose call stubs are compiled ahead of time (aot_thunks = true) should be generated again with wrap(toml). A package that failed to build on 4.5.1 with "multiple definition of" builds now.

v4.5.1 (2026-11-17)

Julia 1.12 stays on the 4.5 releases; update to 4.5.2. This one carries the C++ work that followed 4.5.0; everything in it is in 4.6.0 too.

  • A std::string parameter takes a Julia string, const& or by value.
  • Inline constructors and member functions are callable. A constructor or method that exists only in a header, which the library itself never compiled, is compiled by the build. A constructor or method can also be called with its default arguments left out.
  • [types] records names a header-only class nothing in the library mentions, so it can be built and passed from Julia (Every key).
  • A class that adds only methods to its base has its layout, so it can be passed and returned by value.
  • A class nested in another answers to its full name too (Outer_Inner beside Inner).
  • A C function's int parameter takes an enum value, as C does.
  • One rename to check for in callers: a class whose only destructor is the deleting one is bound as <X>_delete_<X>, no longer <X>_destroy_<X>.
  • Calls that crossed wrong: a uint8 or other narrow enum passed by value to a C++ method read garbage in its upper bytes; a union of a SIMD vector and the array of its lanes was refused.
  • Builds and wraps of large C++ packages are faster, with identical output.
  • Rebuild, then re-wrap, for the string parameters, the inline constructors, methods and default arguments, [types] records and the layouts; a re-wrap is enough for the rest.
  • Known problems in 4.5.1, fixed in 4.5.2 and 4.6.0:
    • A C++ function written with a const number parameter (double scaled(const double x, const int n)) can return a wrong number with no error.
    • A struct whose members are const, returned by value, can make every call stub of its library fail to load.
    • A library with a header that defines functions for one source file only (fmt's format-inl.h, clipper2's clipper.export.h) does not build.

v4.5.0 (2026-11-14)

Every C++ wrapper must be generated again, and the project is rebuilt for the new decoders. The Tier 2 thunk for a function returning a record C++ passes by reference (std::string, std::map, any class with a non-trivial destructor) changed its convention and its name: a wrapper written by 4.4.0 or earlier fails to load with a message saying to re-wrap, instead of calling the old thunk. Linux AArch64 is supported, a std::string returned by value is a Julia String, and overloads that were one method are separate methods. Julia 1.12 is the oldest release supported (Project.toml admitted 1.10 and 1.11, which nothing tested).

  • Linux AArch64. The AAPCS64 struct rules (a homogeneous floating aggregate in floating registers, 16 bytes or less in general registers, larger by reference) on both tiers, and the JIT fixes the first arm64 run needed. CI runs devtests on an arm64 runner. macOS is still refused, and Windows on ARM is not built.
  • std::string returned by value is a String. The wrapper reads the characters where C++ built the object and ends it there; libstdc++'s and libc++'s layouts, char strings only. A string the wrapper cannot decode keeps its bytes, with the reason in a comment beside the call. Needs a rebuild: the layout is recorded at build time. A std::string parameter still takes the byte stand-in (on the Not Yet Built list).
  • std::tuple, std::optional and std::complex by value are callable, laid out from their bases; std::complex<long double> on both conventions.
  • Pass-by-reference returns were built in a dead frame. Every Tier 2 function returning such a record moved the object's bytes out of the thunk's own stack; it held while the bytes meant the same at any address, and libstdc++'s short string does not. The object is now built in the caller's buffer. This is the thunk convention change above.
  • C++ overloads dispatch on a pointer's target and on an enum. GetID(const char*) and GetID(const void*), or f(Kind) and f(int), were one Julia signature, and the one kept was whichever came last. The positions an overload set disagrees on now take a Union of what callers pass (String, Ptr, Ref, a Managed object, an AbstractVector), or the enum itself; every other pointer position stays ::Any. An argument outside that Union is a MethodError where it used to pick an overload. An rvalue overload beside its const& twin is not emitted (a move where the caller meant a copy).
  • [wrap.rename]. A table of key = "julia_name", keyed by the mangled symbol or the derived Julia name (anchored globs), applied inside the one name derivation so every emitter binds the chosen name. For Boost.Math's 600-character template names (TOML reference).
  • Wrapper names and types that change — re-wrap, and update callers:
    • C enums are open types (primitive type E <: RepliBuild.OpenEnums.OpenEnum) instead of @enum: any value of the underlying type is a value (VTERM_KEY_FUNCTION(n)), declared values print by name, undeclared ones as E(v). Integer conversion and ccall passing are unchanged.
    • A pointer or reference return is Ptr{T} when the wrapper emits T (opaque handles included); void*, function pointers and mutable records stay Ptr{Cvoid}. Typing is not ownership: no finalizer is attached.
    • [types] templates entries written through a typedef (std::vector<Point64>) yield the container's table and a factory named as written; an entry that yields nothing is a warning, not an empty table.
  • Graph mode (a CMake project as one package): one Julia type per C++ type across the graph's libraries, and an imported enum brings its values (World.Happy === Hello.Happy); the project can be a pinned [dependencies] checkout ([graph] dependency); object-library sources, versioned sonames and file-local types (libwebp builds).
  • Calls that crossed wrong:
    • A C record whose eightbyte holds a float beside integers or bytes (a union of int and double, a float next to a bitfield) was an ABI trap; it crosses as C does. The last 31 Hub C stubs are calls.
    • A C++ record over-aligned only through a member's alignas was read from the wrong stack slot by ccall; it goes to Tier 2.
    • A derived class whose trivial destructor aliases its base's (tinyxml2's ~XMLComment) carried the base's destructor symbol, so its finalizer ran the base destructor.
    • A method proxy's owner could be collected during a Tier 2 call; it is kept alive across the call.
    • A thunk's callee in the C++ runtime library (a basic_string member the library calls but does not instantiate) binds through the library's own handle; one the handle cannot resolve is dropped with a warning instead of blocking the JIT.
  • Builds and tooling:
    • A git dependency prints its clone and fetch progress at a terminal.
    • The Tier 1 slice cache is per libLLVM major, so two Julia releases on one checkout no longer re-slice each other on every wrap.
    • test/suites.jl is the one list of test files; test/devtests.jl --changed runs what a diff touches. test/tools/cpp_thunk_coverage.jl measures C++ coverage on the Hub as c_ccall_coverage.jl does for C.
  • Fixes in what build extracts — rebuild, then re-wrap: the string layout; toolchain records laid out from bases; destructor attribution for aliased destructors.

v4.4.0 (2026-11-08)

A function that returns or takes std::pair, std::array or std::string_view by value is callable, and a dependency can be a tarball. Generated wrappers change some names and parameter types (below), so this is a minor release.

  • Standard-library records by value. A record the library passes, returns or holds by value keeps its layout when it is declared in a toolchain header, and the wrapper emits it as a struct (pair_double_double, with first and second). This covers std::pair in every shape, std::array, std::string_view, and a library struct with one of them as a member. Only what an exported function crosses by value is kept; the standard library's own internals are not. std::tuple, std::optional and std::complex are still ABI traps. A struct that derives from an empty base (std::pair does, and so does a library struct P : Tag { … }) crosses by value; it was an ABI trap.
  • Archive dependencies. [dependencies.<n>] type = "archive" with url and a required sha256 fetches a tarball (any format Pkg reads), checks the hash before unpacking, and walks it like a git checkout, from subdir or the archive's single top directory. A changed pin fetches again (TOML reference). A local dependency's exclude is now applied, and its headers count as the project's own for the shim-header check.
  • Wrapper names and types that change — re-wrap, and update callers:
    • An enumerator whose name is also a struct, function, global, constant or another enum's member is bound as <enum>_<name> (Boost.JSON's kind::object is kind_object, because object is a struct). Before, the later definition silently replaced it. An enumerator that collides with nothing keeps its name, and a wrapper that would bind any name twice is refused when it is written.
    • A parameter that is a reference to a type Julia cannot hold (long double&, __int128&) is Ptr{Cvoid}, the address of a buffer you own, instead of Ref{Any}.
    • C++ overloads that differ only in an integer parameter's width are separate methods: those positions keep their C type (value::Cint, value::Clonglong), and the rest stay ::Integer.
  • Calls that crossed wrong:
    • A Tier 2 integer argument narrower than its C parameter (Int8 for an int) was read past its storage and gave a different value on every call.
    • A function returning a pointer or reference to a standard container (path::native()) was declared as returning the container itself, and the caller got an address on the thunk's stack.
    • A record with a * or & inside its template arguments (pair<T*, bool>, result<T&, E>) was treated as a pointer; on Windows that was an access violation.
    • SIMD vectors (__m128, vector_size) passed by value, bare or inside a record, crossed lane by lane on both tiers; they now classify by their size or are refused, on Linux and Windows.
    • A C++ name containing \x (a char template argument) failed the whole library's Tier 2 module, and so did two records whose names differ only in punctuation.
    • A record outside namespace std named like a standard one (boost::core::string_view) was skipped as standard-library internal.
  • Builds:
    • A failed build no longer leaves the previous build's project hash, so the next build cannot report "project unchanged" over a broken library. A compiler that never started counts as a failure.
    • Fedora's binutils are recognised as GNU binutils.
  • Fixes in what build extracts — rebuild, then re-wrap: the toolchain records and empty bases above; the scope recorded on each struct (the std check); SIMD vector facts, including a 3-lane vector's size; nounwind for a C++ library linked from several IR modules.

v4.3.1 (2026-10-31)

Multi-library projects build and wrap from CMake's own build graph.

  • Graph mode. A [graph] section (TOML reference) builds a CMake project of several libraries. RepliBuild runs only CMake's configure step and reads its File API: every target, its sources, flags, defines and include path, including what it inherits from the libraries it links. It runs the build steps that write generated sources, compiles and links each library itself (C libraries with Julia's clang, C++ with the system clang), and extracts each one's metadata. wrap writes one wrapper per library and a graph module that includes them in load order, so G.Shapes.f(…) calls a function of the shapes library. A library named like a Julia binding gets an R (Core → RCore). register and use handle the graph as one unit. Types are still per library: a struct two libraries share is a different Julia type in each wrapper.
  • Git submodules. [dependencies.<n>] submodules = ["libs/math"] fetches exactly those submodules of a git dependency, at the commits its pinned commit records, so a library inside a superproject such as boostorg/boost no longer needs a dependency of its own.
  • [wrap] shim_defines builds a single-header library's implementation (STB_IMAGE_IMPLEMENTATION) from the TOML, in the shim file only.
  • C++ finalizers free what they own. A Managed<X> or factory struct calls the library's deleter function for the class, else its deleting destructor; a class with neither gets no owning type. Re-wrap to pick it up.
  • A Tier 2 record holding a template member (std::array, std::pair, a project template) keeps its size when it crosses by value.
  • clean(toml; deps=false) keeps the vendored git clones, so a rebuild from cold checks their pins instead of fetching them again.
  • ingest registers the way discover does: only with build=true, wrap=true, after wrapping. A bare call writes the TOML and nothing else.
  • Pkg.build builds the JLCS dialect on Windows, and rebuilds it after an LLVM minor upgrade.
  • Fixes in what build extracts — rebuild, then re-wrap:
    • Tier 2 on Linux classifies a record passed or returned by value from its DWARF facts, not from the body it crosses as. Records with padding, nested records, unions, bitfields, long double or __int128 crossed wrong.
    • Tier 3 on Linux places a by-value record C aligns to 16 in the stack slot C reads, or refuses the call.
    • Template parameters are read on Linux, and const void * is recorded as itself instead of an unknown type.
    • On Linux every library binds its own exported functions to itself (-Bsymbolic), and Tier 1 slices name them by alias: a library that Julia also loads (zlib) no longer calls Julia's copy.
  • surface_types_only keeps the records a signature spells with template arguments.
  • Header enums come only from the project's own headers, and scaffold_package includes the wrapper file wrap writes.
  • Parallel builds no longer clear the caller's LD_LIBRARY_PATH and CPATH.

v4.3.0 (2026-10-23)

The registry builds a project where it lives; AOT thunks come from wrap. register and use change what they do (below), so this is a minor release. v4.2.1 was never registered: its changes reach users with this release.

  • ABI fixes from the differential fuzzer, which generates C records and functions and checks both tiers against the compiler.
    • Tier 3 (C): whether a record comes back in registers or through a hidden buffer is decided per target, from real alignment; that buffer has the record's alignment; one long double parameter refuses that function, not the whole wrapper; records and enums named after Julia keywords are spelled as declared; a module name never starts with a digit.
    • Tier 2 (C++): unions and bitfield records pass and return by value as their bytes; #pragma pack bodies stay packed; bitfields wider than 32 bits get working accessors.
  • Switching Julia or the C++ toolchain rebuilds what the switch affects.
  • Rebuild, then re-wrap. Member sizes, record alignment, names that several types share, and function-pointer parameters are now recorded in the metadata. The first build also compiles every file once more, because IR file names changed.
  • The registry builds a project where it lives.
    • register builds and wraps the project in place, vendors the build to ~/.replibuild/builds/<hash>/, and adds a Julia package around it to your Julia environment (env, default the @v#.# one). using MyProject loads it from there, and use("myproject") loads it too.
    • use follows edits by rebuilding the project in place, and loads the last vendored build if the project has moved.
    • A bare discover no longer registers anything; discover(...; build=true, wrap=true) ends by registering.
    • The registry no longer copies a project's sources into itself, so two projects with the same relative paths can no longer overwrite each other.
    • A project registered by an earlier RepliBuild keeps building the copy that version made. Register it again, from the project.
  • AOT thunks in one pass. With [compile] aot_thunks = true, wrap compiles the thunks library as its last step, for exactly the thunks the wrapper binds; build no longer compiles thunks. A new package used to need build and wrap twice.
  • The same source wraps the same on Julia 1.12 and 1.13 and after an upstream edit. A regenerated wrapper changes once: lambda closure types are no longer emitted, and where several types share a name, the definition kept is chosen by content.
  • A call that passes by value a type whose name several types share is an ABI-trap stub that says why, instead of using whichever layout was kept.
  • Function-pointer types carry their parameter lists, and a callback's @cfunction example comes from its own typedef or DWARF signature, never from a name match.
  • Windows links are reproducible: the same IR gives the same DLL, so LIBRARY_SHA changes only when the library does. A link longer than one Windows command line goes through a response file.
  • scaffold_package writes a RepliBuild compat entry that admits the RepliBuild that generated the package. It wrote RepliBuild = "2", which resolved RepliBuild 2.x.

v4.2.1 (2026-10-17, released in v4.3.0)

LLVM.jl 10. LLVM.jl compat widens to 9, 10. Tier 1 (experimental, off by default) reads the names LLVM.jl 10 changed the meaning of, so it behaves the same on both, and a Slicer exception demotes that one function instead of failing the wrap. On Windows, [wrap.tier1] allow_setjmp is ignored with a warning. No API change; a 4.2.0 wrapper keeps working.

v4.2.0 (2026-10-16)

LLVM 23 and Windows, end to end. New: [platform.<host>] tables in replibuild.toml, JSON 1.x, the JLCS dialect on LLVM/MLIR 23, and end-to-end coverage of AOT thunks. Behaviour changes: relative [compile] paths resolve against the project root, codegen runs at [link] optimization_level, and a C++ package compiles its .c files with the system clang. A 4.1.1 wrapper keeps working. Build-time fixes, the libc++ exports among them, need a rebuild; generator fixes need a re-wrap.

v4.1.0 and v4.1.1 (2026-09-24, 2026-09-27)

Bounding the wrap surface. RepliBuild.DAGDiff is removed (it was exported), and [wrap] dag is ignored with a warning. New keys, all opt-in: [compile] visibility, [wrap] exclude_symbols, [wrap] surface_types_only and surface_types_extra. [link] link_dirs now emits an rpath as well as -L. 4.1.1 is a patch of generator and DWARF-reader fixes: no new keys, nothing removed, and a 4.1.0 wrapper is unchanged until it is regenerated.

v4.0.0 and v4.0.1 (2026-09-05, 2026-09-13)

  • Windows is supported. x86_64-w64-windows-gnu (mingw, MSYS2 CLANG64) — not MSVC. See Install. macOS is still refused at load, because the AAPCS64 ABI classifier is not built.
  • C bitflag enums are integer aliases, not @enums. This appears when you regenerate a wrapper; existing ones are unchanged until then. An enum whose members are a mask now emits const Flags = Cuint plus named constants, so A | B works and can be passed. Detection is conservative — 59 of 544 enums across the shipped Hub wrappers reclassify — but if you had been matching on an enum instance, or printing one and expecting its name, that is what changed. Ptr{Flags}, ccall arguments typed Flags, and export all behave as before.
  • 4.0.1 made Julia 1.13 (libLLVM 20) work. No API changes.

What still matters from the 3.x line

Calling code written against older generated APIs may need these updates:

  • A pointer parameter takes a pointer or a Ref. Overloads that accepted a struct value for an S* parameter were removed: the callee got a pointer to a temporary copy. A by-value struct parameter still takes the value.
  • char* returns are Union{String,Nothing}. NULL is nothing, not an exception. Declare malloc'd returns in [wrap.cstring_owned]. Every such function has a raw <name>_ptr sibling.
  • [wrap.varargs] lists Julia types, variadic arguments only, as a list of lists: f = [["Cint"]]. C types belong in [wrap.macros], not here.
  • discover(force=true) preserves hand-edited keys (templates, macros, varargs, shim headers, cstring ownership). Keep the rest of a hand-written config in version control anyway.
  • Vendored wrappers resolve their .so sibling-first, so a copy in lib/ stays bound to the .so next to it.
