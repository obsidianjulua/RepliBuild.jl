## Project Overview

RepliBuild.jl is an ABI-aware C/C++ compiler bridge for Julia. Compiles C/C++ through LLVM/MLIR, introspects DWARF metadata, and emits type-safe Julia bindings. Functions are routed to one of three tiers — `llvmcall` (Tier 1), MLIR AOT thunks (Tier 2), or `ccall` (Tier 3) — based on ABI complexity.

```bash
# Lightweight CI tests (no C++ toolchain required)
```

## RepliBuild API

### Step-by-step workflow

```julia
using RepliBuild

# 1. Scan project, generate replibuild.toml
toml = RepliBuild.discover("path/to/project")

# 2. Compile: Clang → LLVM IR → .so + DWARF metadata
RepliBuild.build(toml)

# 3. Generate Julia wrappers from DWARF + symbols
RepliBuild.wrap(toml)

# 4. Load the generated module
include("path/to/project/julia/MyProject.jl")
using .MyProject
```

### One-call shortcut

```julia
# discover + build + wrap in one call
RepliBuild.discover("path/to/project", build=true, wrap=true)
```

### Ingest mode (BYOB — bring your own build) — EXPERIMENTAL, C only

**Status doctrine (2026-07-18, issue #4):** ingest is a fallback, NOT a flagship
feature, and is not hardline-maintained the way the source pipeline is. It is
experimental, best-effort, and **C only** — the C++ API surface of an ingested
binary is unsupported (classes/methods/templates/virtual dispatch need the MLIR
dialect thunks only the source build generates; at best the `extern "C"` surface
works). `ingest()` and `ingest_library` both warn accordingly; README + docs say
the same. Don't re-inflate the claims when editing docs.

For **C** libraries with elaborate build systems (autotools, CMake with code
generators, configure scripts) that RepliBuild's source-build pipeline can't
reproduce, build upstream yourself and ingest the resulting `.so`. RepliBuild
skips compilation — only DWARF metadata extraction + wrapper generation runs. The
`.so` must be built with `-g`. Ingested libraries dispatch through Tier 3
(`ccall`) only, and extraction quality depends on upstream's compiler and
debug-info settings.

```julia
# Scaffold an ingest config
toml = RepliBuild.ingest("/path/to/libfoo.so",
                         headers=["/path/to/include"],
                         name="foo",
                         language=:c)

# Or run the whole pipeline immediately
toml = RepliBuild.ingest("/path/to/libfoo.so",
                         headers=["/path/to/include"],
                         build=true, wrap=true)
```

The generated `replibuild.toml` carries an `[ingest]` section that flips RepliBuild
into ingest mode — its presence is the mode switch:

```toml
[ingest]
library = "/path/to/libfoo.so"
headers = ["/path/to/include"]
extra_link_libs = ["libbar.so.1"]    # optional — dlopen'd RTLD_GLOBAL before the
                                     # main library, so its undefined symbols can
                                     # resolve against them
```

**`extra_link_libs` was INERT until 2026-08-26** — parsed, documented as loading
libraries, serialized back out, and read by nothing. `test_ingest.jl` "covered" it
by asserting the value round-tripped through the PARSER, which is true whether or
not the feature exists; that is the same class as "a WRONG harvested config does
not fail the build". Now emitted as an `__init__` prologue in **both** generators
(`_extra_link_libs_snippet`, Wrapper/Utils.jl), spliced ahead of every `dlopen` —
opened afterwards they would resolve nothing. Guarded by `test_config_surface.jl`,
which EXECUTES the emitted snippet, and which additionally requires every
`RepliBuildConfig` field to be consumed or named in `RESERVED_UNUSED` with a
reason. Nine were inert when that guard was written: `[binary] strip_symbols`, the
whole `[discovery]` section, `[wrap] enabled`/`style`, `[workflow] stages` (only
reachable via `is_stage_enabled`, which has no callers), `[project] uuid`, and
`[paths] source`/`include`/`cache`.
**Prefer a full soname or path over an `-l` name**: `-l` is a link-time spelling,
and on glibc ≥ 2.34 `m`/`pthread`/`dl`/`rt` are merged into libc with
`/usr/lib/libm.so` a linker script, so `-lm` links while `dlopen("libm.so")`
fails. The wrapper warns and continues — correct, since there is nothing to
preload.

**GENERATED `config.h` IS NO LONGER A DISQUALIFIER — cmake's configure step is capturable (built 2026-08-17).** The admission rule "no configure step" ruled out every library whose headers come from feature detection, which is a large fraction of real C. But **cmake's configure is not its build**: it is a self-contained detection pass that emits the generated headers in seconds without a compiler touching a real source file, and with `CMAKE_EXPORT_COMPILE_COMMANDS` it also states exactly how upstream compiles every TU. libcurl was unblocked this way by hand (`packages/curl/config/README.md`); this generalises it. `cmake_probe` (configure only) → `harvest_config` (copy generated files into `packages/<name>/config/`, write provenance) → `propose_toml`.
  - **Three things come out of `compile_commands.json`, and the last two matter more than the headers**: the exact `-D`/`-I` set; a **mechanical** uniformity verdict (does every TU of a target share one flag set — the admission question, previously eyeballed); and the **exclude list** as `every .c/.cpp in the tree` minus `the TUs the chosen target compiles`. On pcre2 that derivation produced the same 13 exclusions a human would write, including the four non-obvious groups (`#include`d-not-compiled JIT/ucptables files, `main()` tools, the separate posix target, non-library fuzz/debug code).
  - **A project configures the SAME sources into several targets — shared + static + a compat shim is the norm — and that is not flag divergence.** First cut reported pcre2 as "3 distinct flag sets, NOT uniform" when it is 4 clean targets. Uniformity is judged **per target**, targets are read off `CMakeFiles/<target>.dir/` in the `output` field (the only place the target name appears), and `main_target` prefers the shared one. Getting this wrong makes the tool reject admissible libraries.
  - **`cmake 4.x` hard-errors on `cmake_minimum_required` below 3.5**, so `-DCMAKE_POLICY_VERSION_MINIMUM=3.5` is on by default — without it libyaml 0.2.5 fails to configure at all. Also: the probe runs cmake under `with_llvm_env` by default, so feature probes are answered by the same clang that will compile the sources (the one place this beats doing it by hand — a header captured from the system compiler can disagree with the toolchain that consumes it).
  - **BOUNDARY — configure-time generation works, build-time generation does not.** libpng is the type case: `pnglibconf.h` comes out of an awk pipeline wired as a *custom command*, so a configure-only probe yields nothing. `generated_headers` coming back empty IS the signal, and `harvest_config` warns accordingly. Check for a shipped fallback before giving up — libpng ships `scripts/pnglibconf.h.prebuilt`, checkable in with no cmake at all. Autotools `./configure` is **untested**; the same trick plausibly applies, don't claim it works until someone runs it. Note the boundary is *when*, not *whether*: pcre2's `pcre2_chartables.c` is a code-generator output and harvests fine, because upstream's default is `configure_file(COPYONLY)` of a checked-in `.dist` rather than compiling and running `pcre2_dftables`.
  - **A harvested config is a single-target pin and a WRONG one does not fail the build** — it produces a library that is self-consistently *not* the library (no Unicode, a 32-bit size type), which compiles, links, wraps clean and passes shallow `isdefined` tests. So the package test must assert **behaviour that depends on the probes**. `packages/pcre2/test.jl` compiles `\p{L}` against a UTF-8 subject with a multi-byte char (proves `SUPPORT_UNICODE` is real, and pins byte-offset semantics) and reads the version back out of the built `.so` via `pcre2_config_8`. Each package gets a `harvest.jl` regeneration driver that pin-checks the clone's HEAD and **errors if the chosen target stopped being uniform**; run it on a version bump and diff `config/`.
  - **pcre2 10.45 shipped as the reference (2026-08-17)**: 30 TUs (29 library + the macro shim), 1.36 MB, build **7.5s**, **119** DWARF functions (105 library + 14 macro shims) with real signatures — `pcre2_compile_8` recovers all 6 params typed, no zero-arg smell — 236 wrapper functions, **test.jl 77/77 from clean**. Exercises three harvest shapes at once — a `config.h` of 47 feature-probe results (31 set, 16 left undef; the "122 probes" figure belongs to curl, not pcre2), the *public* header (`pcre2.h` is `configure_file`'d from `pcre2.h.in`, so it does not exist in git), and a generated `.c` that must be compiled. That `.c` lives in `config/`, not the clone, so the resolver's walk never sees it: it is named in `[compile] source_files`, which **merges with** resolver-discovered sources rather than replacing them (`DependencyResolver`, `unique(vcat(...))`). `config/` is first in `include_dirs` because this box has a distro `/usr/include/pcre2.h` — an explicit `-I` outranks the system path, and `verify_shim_headers` fails loud if it ever doesn't.
  - Public pcre2 names are macro aliases (`pcre2_compile` → `PCRE2_SUFFIX(pcre2_compile_)` → `pcre2_compile_8`); the `_8` symbols are what exist in the `.so` and what DWARF reports, and are deliberately NOT alias-shimmed — an alias layer would hide the code-unit width the whole build is pinned to. The 14 `[wrap.macros]` entries are the constants only, typed off the header (`uint32_t` option bits, `size_t` sentinels), since `PCRE2_ANCHORED = 0x80000000u` and `PCRE2_ZERO_TERMINATED = ~(size_t)0` both wrap to negative if shimmed as `int` — a silent-wrong-value class the test asserts against directly.
  - Tooling suite **133/133** (adds unit tests for the parsing internals plus a self-contained cmake fixture — a generated `CMakeLists.txt` with a `configure_file`, a live source, an orphan source and a `tools/` dir — so the probe→harvest→propose path is tested without any network or vendored library). `hub-wrap` SKILL.md Phase 1 updated: it previously rejected this entire class outright.

## Architecture

### Pipeline

```
C/C++ Source → DependencyResolver → Discovery → Compiler (Clang → LLVM IR)
  → Linker (.so + LTO bitcode) → DWARFParser (llvm-dwarfdump + nm)
  → Wrapper Generator (Julia module) → JITManager (on-demand MLIR thunks)
```

### Three-Tier Dispatch

| Tier | Mechanism | When Selected |
|------|-----------|---------------|
| 1 | `Base.llvmcall` — **two different payloads**, see below | POD args, scalar/pointer return |
| 2 | MLIR AOT thunks via libJLCS.so | Packed structs, unions, large struct return, virtual dispatch |
| 3 | `ccall` | Fallback when bitcode unavailable |

**Which Tier-1 payload you get (verified in the generator 2026-07-25):** the C
generator has TWO independent Tier-1 paths and they are selected by different
knobs.
- `[link] enable_lto` (**default true for C**) → the old **whole-module** path:
  the wrapper carries `LTO_IR` (the entire linked module) and each call site
  emits `if !isempty(LTO_IR)` + `llvmcall` on it (`lto_eligible`,
  GeneratorC.jl ~2196). This is the parked, scale-limited one — read both
  caveats below.
- `[wrap.tier1] enable` (**default false**) → the **sliced** path
  (`tier1_this`, ~2201): a per-function declarations-only slice, immune to both
  caveats. Requires `lto_shape_ok && c_safe` on top of slice acceptance.

So a C project on default config today still gets the *whole-module* path, not
the sliced one — slicing is opt-in. Retiring `enable_lto`'s call-site emission
in favour of slices (or flipping `[wrap.tier1] enable` to default-on once M4
lands) is an open decision, not an oversight.

**Tier 1 whole-module scale caveat (verified 2026-06; applies to the `enable_lto` path only):** LTO is the **C default** (`default_lto = language==:c`, [ConfigurationManager.jl:335](src/Builder/ConfigurationManager.jl#L335)), so `is_c_lto_safe` functions (everything except packed-struct / union *returns* — see `DispatchLogic.jl`) route to Tier 1. BUT `Base.llvmcall` embeds the whole linked module per call and **segfaults at whole-library scale** on Julia 1.12.6 (e.g. box2d3's 730 fns); toy 1–2 fn modules work. So production Hub configs set `[link] enable_lto = false` to force Tier 3 `ccall` (calls the `.so` directly, no embedded IR). The whole-module payload is **scale-limited and effectively parked**; the fix was per-function bitcode slicing, not whole-module embedding — built out M1–M3 below. C++ defaults LTO off → Tier 2/3.

**Tier 1 whole-module state caveat (verified 2026-07-11; killed by M1 on the sliced path):** whole-module embedding also **duplicates file-local statics** — the IR globals-externalization pass deliberately keeps `static`/internal-linkage definitions local to the bitcode (no .so symbol to bind to), so mixed Tier-1/Tier-3 dispatch diverges on internal state. Observed live on cJSON: llvmcall'd `cJSON_Parse` wrote the parse error into the *embedded* copy of `static global_error`, while ccall'd `cJSON_GetErrorPtr` (Cstring return → never Tier 1) read the `.so`'s copy — error reporting silently returned NULL after every failed Tier-1 parse. Stateless calls are unaffected. This is a second, scale-independent reason Hub configs pin Tier 3 (cjson + zlib flipped 2026-07-11; all Hub configs now `enable_lto = false`). **Static promotion (M1) removes this class from the sliced path by construction** — there is one copy of the state and slices bind it by symbol — so it is a caveat about `enable_lto`, not about Tier 1 as such.

  **Slices are precompile dependencies (2026-07-28):** each Tier-1 function emits `const _SLICE_<fn> = read($path, String)` **plus `include_dependency($path)`**, both built from `_slice_path_expr(mangled)` so they can't drift. `read` alone satisfies `Base.llvmcall`'s statically-evaluable-IR requirement but registers nothing with the staleness check, so a vendored wrapper would serve an edited slice out of a stale `.ji`.   **Portability guards (2026-08-02) — a generated wrapper is portable SOURCE, and the library beside it at runtime need not be the one it was generated from.** Vendoring the wrapper onto a JLL, a distro package, or any independent rebuild hits two silent failures, so each got a guard emitted INTO the wrapper (wrappers cannot depend on RepliBuild at runtime, so both helpers are generated inline):
  - **Load-time symbol check** (`_slice_symbols_resolve` + `TIER1_DECLARES`). The wrap-time pre-flight validated against a *different file* than the one present at runtime — and a foreign build has none of the `__rb_*` promoted statics, so those declares are unresolvable and ORC **blocks forever** on first call. Each `@generated` kernel now dlsym-checks its slice's declares before trusting it; a miss silently takes the ccall body, which is always correct. `TIER1_DECLARES` is recorded off the **shipped `.ll` files** (`_slice_declared_symbols`), not carried over from the Slicer, so the table and the file it guards cannot disagree. miniaudio ships 199 entries.
  - **Build identity** (`BUILD_ID`/`BUILD_TARGET`/`BUILD_GENERATOR` + `_check_build_identity` in `__init__`). GNU build ID read from **PT_NOTE, not a section header**, so it survives `strip`. Warn-only by design: a same-source rebuild is usually fine and refusing to load would break real workflows, but layout drift (struct offsets, blob sizes, enum values are all a snapshot of ONE compilation) is silent and unrecoverable at the call site, so the user is told once. Tier 1 protects itself separately and automatically.
  - Proven end-to-end in `test_tier1_dispatch.jl` §"Portability guards": a plain `clang` build of the same sources (no promotion pass → no `__rb_*`, exactly what any non-RepliBuild build looks like) is staged next to the wrapper and driven in a subprocess. It warns with both build IDs, demotes every promoted-static slice, and still computes correctly — **that call site is where the process used to hang**.

  **Slice symbol pre-flight (2026-07-25, `_tier1_preflight!`; scoping fixed 2026-07-28):** an unresolved slice `declare` does NOT raise — ORC prints `JIT session error: Symbols not found: [...]` and then **blocks forever** on the first call (verified by killing a 180s run). So before any slice reaches disk, the pre-pass dlopens the `.so` and `dlsym`-checks every name in `SliceResult.declares`. A miss demotes that function to Tier 3 with a warning naming the symbol; an un-dlopenable `.so` disables Tier 1 wholesale rather than shipping unverified slices. `declares` is recorded post-DCE by the Slicer (intrinsics excluded) and round-trips through the slice cache (`SLICER_VERSION` 3). This converts the whole "unresolved symbol → JIT deadlock" class into a clean ccall fallback — same discipline as the macro-shim collision guard.

  **The lookup is scoped to the LIBRARY, not to the process (2026-07-28).** The original checked `dlsym(RTLD_DEFAULT, …)` after an `RTLD_GLOBAL` dlopen it never closed — so every wrapped library's symbols stayed in the namespace for the rest of the session. Wrapping B after A verified B's slices against **A's** exports; re-wrapping after an edit verified against the **previous** `.so`. Those symbols do not exist in a consumer's process, so the slice ships and deadlocks there — the exact class the pre-flight exists to prevent, reintroduced by the pre-flight's own side effect. Now: `RTLD_NOW | RTLD_LOCAL`, resolve through the **handle** (the `.so` plus its `DT_NEEDED` chain — what a consumer gets when `__init__` dlopens it `RTLD_GLOBAL`), `dlclose` in a `finally`. Handle scope is strictly narrower than ORC's process-wide lookup, so it can only over-demote (safe), never wrongly accept. A symbol that misses through the handle but *does* resolve process-wide is reported as a separate "stray" warning — "missing" and "only resolves because something else is loaded here" have completely different fixes. Gated in test_slicer §"M3 symbol pre-flight": `jl_gc_collect` (real libjulia symbol, not supplied by the fixture `.so`) must be rejected, and a private copy of the `.so` must be absent from `Libdl.dllist()` after the check.

  **Embedding an internal constant requires `unnamed_addr` (2026-07-28, `_addr_insignificant`).** The old boundary policy embedded every internal constant with the rationale "no symbol exists; duplication is harmless". Harmless only if the ADDRESS is dead: the `.so` keeps its copy and the JIT gets a second one elsewhere, so any pointer comparison, sentinel check, or stored-then-compared address answers differently depending on which tier ran. **That is the cJSON divergence class rotated from value identity onto address identity, and just as silent** — M1 does not cover it, because promotion deliberately exempts internal constants. LLVM already marks exactly this property, so the gate is `unnamed_addr || local_unnamed_addr` (local suffices: the global has internal linkage, so nothing outside the library can name it and "not address-significant within the module" covers every observer that exists). Without it → refusal naming the constant, not a hazard: embedding produces *wrong* IR, not risky IR, which matches the sibling `internal-linkage mutable global` refusal. **Cost, measured: 18 of 208 lua functions demote** — `absentkey` and `dummynode_` (`lua_getfield`/`geti`/`seti`/`rawgeti`/`getglobal`/`createtable`/`getinfo`) and the `luaL_Reg` tables (every `luaopen_*`). - **Thunk arg-slot conventions (don't mix them up — cost a debugging session 2026-07-16):** FunctionGen slots hold a pointer to the argument's *storage* — one load yields a struct's address (or its value via a second load), and pointer args double-load. Callers packing by-value struct args put `&struct` in the slot directly, not `&Ref`.
- **By-value struct ABI in `try_call`/`ffe_call` lowering (fixed 2026-07-18):** `classifySysVStruct` (JLCSPasses.cpp) decides MEMORY vs register class per x86-64 SysV. MEMORY (>16 bytes, or a genuinely misaligned field) keeps sret / pointer conventions; register-class structs (≤16B, aligned — includes everything `is_struct_packed` over-classifies) coerce **one scalar per eightbyte** (INTEGER→i64, SSE-only→f64), clang-style, for returns AND by-value args. The old rule ("packed → always sret") shifted every native arg by one register — pugixml `first_child` returned JIT-code addresses as node handles. Self-JIT'd callees can NOT catch such mismatches (both sides share the convention); only a system-clang callee can — that's what `test/test_struct_abi.jl` §C does.
- **EMITTED STRUCT SIZE ≠ DWARF `byte_size` — a live heap smasher on every Tier-2 MEMORY-class struct return (found + fixed 2026-08-05, `StructGen.jl`).** A non-packed struct was closed with ONE trailing filler of `byte_size - sum(member sizes)`. That double-counts: LLVM inserts the *interior* alignment padding itself, and DWARF reports enum members with `size = 0`, so the filler paid a second time for gaps the natural layout had already paid for. **Every non-packed struct with interior padding came out larger than the C type it models.** Since `llvm.emit_c_interface` stores a MEMORY-class result straight into the caller's buffer — and JITManager's `_invoke_call` supplies a `Ref{T}` sized from the JULIA struct, i.e. the true `byte_size` — every such call wrote past a live Julia object. Measured on llama.cpp: `llama_context_params` emitted **200 bytes against a native 160** and `llama_context_default_params()` wrote **34 bytes past a 160-byte `Ref`**; `llama_model_params` 80 vs 72, **8 bytes past**. **Every member offset held the right value**, which is why it presented as intermittent corruption — a garbage `n_ctx` read in one session, an outright SIGSEGV in the next — and got misdiagnosed as "160-byte struct return is corrupt while 72-byte is correct". It was never a marshalling bug; both structs marshalled perfectly and then overran. Fix: `_dwarf_padded_members` lays members out at their **DWARF offsets** with explicit `!llvm.array<N x i8>` padding, verified against a Julia mirror of `abiSize`/`abiAlign` (`_mlir_layout`) — one shared derivation (`_apply_dwarf_layout`) for all three body builders (`get_struct_definition_string` / `_llvm_equivalent_` / `_llvm_aligned_`), since the identical filler line was copy-pasted in each. A struct that cannot be laid out consistently (overlapping members, a member whose emitted type won't sit at its offset, an unmeasurable type, `sum > byte_size` — which used to fall through with no filler AT ALL and ship the oversized body) **degrades to a `byte_size`-byte opaque region and warns**: opaque, but never the wrong size. Cost on llama.cpp: **57 of 2864** structs degrade — libstdc++ regex/STL internals and C++ impl classes. It was 101 when this guard first ran: the other 44 were the ggml quant blocks and their neighbours, whose fixed-size array members `map_cpp_type` rendered as `!llvm.ptr` (a *pre-existing* mapping gap this guard newly surfaced; those bodies were silently wrong before). That is fixed in the same commit — see the fixed-size-array entry — so **no `block_*` degrades today**; re-measured 2026-08-05 after the array fix landed. Warnings capped at 10 + a summary; full set in `StructGen._LAYOUT_WARNED`. **Blast radius is every Tier-2 package** — pugixml's `xml_parse_result` (24B, 3 members summing to 8) emitted 40 bytes and had been overrunning its `Ref` by 16 on every `load_string` since it shipped. Gated by `test/test_struct_layout.jl` (18 asserts, **no toolchain**, in runtests) — negative-checked by redefining `_apply_dwarf_layout` to the old rule, which measures 32 for both 24-byte fixtures.
- **MEMORY-class by-value struct ARGS: `llvm.byval` (built 2026-08-05, closes the standing ledger entry).** SysV passes a >16-byte (or misaligned) by-value struct as a **caller-owned copy in the outgoing stack argument area**. The lowering did neither shape right: packed structs went as a **bare pointer** (by reference — the callee reads an address where it expects bytes), non-packed ones as an **LLVM first-class aggregate** (the backend splits it per ELEMENT across registers, which is LLVM's own aggregate convention, not SysV's, so every later argument shifts too). Both now take one path: alloca + store + pass the pointer with `llvm.byval(T)` + `llvm.align`, stamped on **both the call site and the declaration** (the call site is what the backend lowers; the declaration is what the verifier checks it against). Emitted IR matches clang exactly — `declare i64 @gap_probe(ptr byval(%Gap) align 8)`. Slot alignment for sret AND byval is now explicit (`memorySlotAlign` = `max(8, abiAlign)`) so a degraded `!llvm.array<N x i8>` blob, whose natural align is 1, can't hand native code an underaligned buffer. **`ffe_call` and `try_call` carried independent copies of the whole coercion** — that is how a fix to one silently misses the other — so it is now one `buildSysVCallShape` + `byValArgAttrs` + `retargetCallee`. Gated by `test_struct_abi.jl` §D (15 asserts, drives the **whole generator** metadata→StructGen→FunctionGen→lowering against a real clang++ callee, not hand-written IR, because half the bug lives in StructGen). Negative-checked: pre-fix dialect returns 22000000 instead of 11022105 from `gap_probe`. Note `b3_sum` (packed path) *passes* pre-fix on this fixture — the thunk's alloca happens to land where the callee looks for its stack copy — so **`gap_probe` is the discriminating case; keep it that way**.
- **`!jlcs.c_struct` must never appear inside an `!llvm.struct` body** (fixed 2026-07-18): the type converter treats `!llvm.struct` as legal and never rewrites its body (signature positions DO get rebuilt as `"_Converted.<name>"`, body-op types do not), so a nested c_struct alias survives lowering and segfaults `translateModuleToLLVMIR` (`PtrLikeTypeInterface::getMemorySpace`) — this was the pugixml whole-process load crash.   **Mechanism, and it needs nothing built.** Three pieces that were each added for their own reasons and compose into a debugger: (1) `options.enableGDBNotificationListener = true` ([impl/JLCSCAPIWrappers.cpp:343](src/mlir/impl/JLCSCAPIWrappers.cpp#L343)) so ORC registers every JIT'd object with gdb through `__jit_debug_register_code`; (2) MLIR's **parser** stamps every op with a `FileLineColLoc` naming its buffer (already noted at [MLIRNative.jl:122](src/IRGen/MLIRNative.jl#L122)) — nothing in `src/` constructs one; (3) the `.debug/mlir/jlcs_<hash>.mlir` dump is the file those locations point at, so it is not diagnostic output, it is **the debugger's source file**. `clean()` removes `.debug` and that is fine — it regenerates at the next JIT init from the module text ([RepliBuild.jl:701](src/RepliBuild.jl#L701)), so the capability is self-healing.

Don't re-derive it.

  ```bash
  timeout -s KILL 175 gdb -batch -nx \
    -ex 'set pagination off' -ex 'set confirm off' -ex 'set listsize 4' \
    -ex 'handle SIGSEGV nostop noprint pass' \
    -ex 'set breakpoint pending on' \
    -ex 'break _ZNK5Base15get_aEv_thunk' -ex 'run' \
  ```

  **Two worked readings, both from `mi_test`, both things this repo previously reasoned about instead of observing:**
  - *The arg-slot double-load* — the convention below that "cost a debugging session 2026-07-16" is now three instructions you watch. `126 llvm.load %arg_ptr_1` → `mov (%rdi),%rax` (slot → storage address), `127 llvm.load %val_ptr_1` → `mov (%rax),%rdi` (storage → `this`). Walked live: `$rdi = 0x7fffffff41f0` → `0x7fffffff4200` → `0xf639d0` (the heap object).
  - *The vcall slot arithmetic* — `128 "jlcs.vcall"(...) { slot = 2 : i64 }` → `mov 0x10(%rax),%rax`. 2 × 8 = 0x10, checkable by eye. `may_throw` is visible too: the `endbr64` + `movabs` block at `+38` is the landing pad, so the indirect-invoke EH lowering is a separate block you can see rather than a claim about the lowering.
  **What this changes.** Every ABI assertion in this file — eightbyte coercion, `byval` vs aggregate splitting, sret buffer sizing, vtable coordinates — moves from *reasoned* to *checkable*. The 2026-08-05 heap smasher (`llama_context_params` emitting 200 bytes against a native 160) would have been `break` → `finish` → `x/25gx` on the sret buffer: minutes, and no misdiagnosis. The two ledger items that need ABI work — vcall for struct-shaped virtual signatures, and the multi-target classifier — both get much cheaper when the register file is observable instead of inferred.
  **And because the DWARF is real and standard, the whole gdb ecosystem applies** — TUI, frontends, record/replay, the usual extensions. Untested here, but it follows from valid debug info rather than from anything RepliBuild would have to support. Whether gdb stays a system dependency or gets vendored as a JLL is deferred; nothing about the mechanism depends on which.

It surfaced from an unrelated question about what the JIT was registering.

  **NOTHING LINKS GDB, and the JIT-debug symbols are Julia's, not ours (verified 2026-08-08).** libJLCS links zero gdb/libbfd/libopcodes; `Debug` shells out to `objdump`/`llvm-dwarfdump`; `rbdbg` drives the system gdb binary. The only ABI is LLVM's **GDB JIT interface**, where we are the publisher and gdb reads the struct out of the inferior — no gdb code in the process. And `info symbol &__jit_debug_descriptor` resolves to **`libLLVM.so.18.1jl`, Julia's bundled copy**, not the system LLVM 22.1 that libJLCS statically links: it loads first, the symbol is global, the dynamic linker wins. ## Not Yet Built (roadmap, not bugs)

RepliBuild is a from-scratch architecture where the mechanics are invented one at a
time. On this kind of project **absence is the default state, not a failure** — a
feature that doesn't exist is an unbuilt piece, not a defect. Only something that
contradicts what *is* built is a bug. This ledger tracks known-unbuilt pieces so they
are recorded rather than rediscovered and mislabeled. Add to it (don't file as bugs)
when you hit a non-existent feature; cite a verifying trace, and date the entry.

For anything ABI-shaped below (the vcall struct-signature gate, the multi-target
classifier), **start with gdb on the thunk** — see "GDB DEBUGS THE DIALECT AT SOURCE
LEVEL" in the MLIR Dialect section. Register state is observable now; these entries
were all written while it was only inferable, and they are cheaper than they read.

- **Array-view Julia-side accessors + rank ≥ 2** — the DWARF-driven *producer* for the
  strided-array ops is built (`ir_gen/ArrayViewGen.jl`: rank-1 get/set thunks over
  fixed-size primitive array members, executing through the JIT — see
  `test_jlcs_producers.jl`, 2026-07-16), but `GeneratorCpp.jl` does not yet emit the
  user-facing Julia accessor functions that call these thunks, and multi-dimensional
  array members (`T [N][M]`) are skipped by the producer's rank-1 regex. The dims/rank
  fields of the descriptor are populated but unused by the lowering (only data + strides
  are read) — bounds checking would build on them.

- **Multi-target ABI classifier** — **Win64 BUILT 2026-08-24, AAPCS still unmodeled.**
  The classifier now selects between two conventions behind `enum class AbiTarget
  { SysV, Win64 }`; `classifyWin64Struct` implements Microsoft x64 as a separate and
  much narrower algorithm rather than a variation on SysV. On Linux `kHostAbi` stays
  `SysV`, so the change is behaviourally inert here, and a non-x86-64 build is an
  `#error` rather than a silent misapply of x86-64 rules to AAPCS.
  **`-DJLCS_FORCE_ABI_WIN64`** compiles the Win64 rules into a Linux `libJLCS.so`
  that cannot run anything (the JIT would emit Win64 calls into a SysV process) but
  can be inspected — the only way to exercise the Win64 *lowering*, not just the
  decision table, without a Windows host. Build it to a scratch path, never over the
  working `libJLCS.so`.
  **`test_win64_abi.jl` (devtests §6b, 95/95) is a SPECIFICATION test and the
  distinction is load-bearing**: `test_struct_abi.jl` proves the SysV path by calling
  a real clang++ callee, because a self-JIT'd callee shares the JIT's own convention
  and cannot catch a mismatch — and that trick is unavailable here, since a Win64
  callee cannot be loaded on Linux. The oracle is clang lowering the same signatures
  for `x86_64-w64-windows-gnu`. **It catches an encoded rule that disagrees with
  clang; it does NOT prove the lowering runs correctly on Windows.** Until a Windows
  host exists the Win64 path stays unproven in the way that matters.
  Four pinned divergences from SysV, three of them silent: size is the only criterion
  (1/2/4/8 in a register, everything else indirect, *including* the 9–16 byte band
  SysV splits across two registers); aggregates never reach XMM (`{float,float}` is
  `i64` here, XMM0 under SysV); coercion is `iN` of the struct's own size, not always
  `i64`; indirect arguments take **no** `byval` attribute.
  Placed at §6b rather than at the end **deliberately** — a failing top-level testset
  aborts the rest of `devtests.jl` and §13 is a standing red, so anything after it
  does not run in-suite. It also needs only clang (no JIT, no `libJLCS`, no built
  fixture), so it belongs with the cheap probes regardless. Its unavailable-oracle
  path is a **skip, never an `exit`**: `exit(0)` inside an include ends the whole
  suite with a success status, and standalone the two are indistinguishable.
  (verified 2026-05-29; classifier rewritten 2026-07-18; Win64 added 2026-08-24)

**DWARF phantom-parameter leak — fixed 2026-07-26 (`free_opaque`, c_abomination_test):**
- **Symptom:** `free_opaque` (one C parameter) came out as `free_opaque(state, next)` with a matching two-argument `ccall` against a one-argument function. Wrong Julia signature AND wrong ccall arg tuple — a silent wrong-call class, not a cosmetic one.

Chain: the *unnamed* formal param of the `InnerFunc` `DW_TAG_subroutine_type` left `current_param_offset` open (unnamed ⇒ never consumed ⇒ never reset) → it survived its own `Abbrev 0` terminator and the following DIEs → the next `DW_AT_name`/`DW_AT_type` it saw were `SelfReferential`'s first member `next` → pushed onto `params_for_this_function`, which was **stored live** in `return_types["free_opaque"]`, so the push retro-mutated an already-finished function. **ANONYMOUS STRUCT/UNION SUPPORT in the C generator — built 2026-08-01.** An aggregate DIE with no `DW_AT_name` (a C11 `union {...};` member, or the type of a `union {...} u;` member) was dropped on DWARF export and the member referencing it typed `Any`. That one unresolvable member failed `_resolve_exact_layout`, so the **whole enclosing struct** collapsed to an opaque blob. Live: tomlc17's `toml_datum_t` (40B) and `toml_result_t` (256B) had **zero named fields** — parse a document, read nothing back. Not a debug-info gap (`llvm-dwarfdump` showed the full tree; `-fstandalone-debug` changed nothing) — NOT the box2d limited-debug-info class.

  Three defects, all in the export path, `Compiler.parse_dwarf_dump`: (1) `resolve_type` had **no `"union"` branch** — `kind in ["struct","class"]` — so *every* union-typed member, named or anonymous, resolved to `"unknown"`; same omission in the `struct_names` collection. (2) anonymous aggregates were filtered out of `struct_defs` by the `unknown_union`/`unknown_struct` name guard. (3) `flush_pending_member` dropped nameless members outright, losing C11 anonymous members entirely. Fix: a **fixed-point anonymous-aggregate naming pass** (runs after the typedef-name propagation, before `struct_names`) names each unnamed aggregate after the member that embeds it — `Parent_u`, or `Parent_anonN` for a nameless C11 member, which also gets `_anonN` as its FIELD name plus an `anonymous_member` flag. Parent-first + iterated, so nested anonymous aggregates inherit their parent's synthesized name; deterministic (sorted key order); members still nameless afterwards are purged as before.

  Generator side (`GeneratorC.jl`): an anonymous aggregate is emitted as an **immutable, correctly-aligned opaque region** and registered in `resolved_layouts`, which is what lets the parent keep real named fields. `_dwarf_member_align`/`_dwarf_aggregate_align` derive alignment structurally from DWARF (bitfields contribute their base type's; `nothing` on any unknown leaf — never guessed), and `_aligned_region_storage` picks an element type that CARRIES it (`NTuple{4,UInt64}`, not `NTuple{32,UInt8}` — align-1 storage under-aligns the parent and shifts every field after it). Named unions keep the existing `mutable struct` + `get_*`/`set_*!` API untouched (6 Hub wrappers depend on it) — and are excluded from the region path *because* mutable is a reference when used as a field, so it could never be embedded in the parent that declared it.
  - **SysV class rule:** an eightbyte is SSE only if EVERY overlapping field is float/double, so an integer element is correct for any aggregate with a non-float member; an **all-float** union (`_struct_all_float_members`) gets `Float64`/`Float32` instead. **Negative-checked** — forcing `UInt64` makes `floatbox_get` return the wrong register file (fixture §7).
  - **`abi_class_risk`** keeps the by-value refusal alive across the representation change: a ≤16B region standing in for a MIXED float/integer aggregate can only claim one class per eightbyte, so it (and, transitively, anything embedding it — emission is topological, one hop per struct) is flagged and the existing `blob_abi_offenders` guard refuses loudly. Without this the guard would have been silently lost, since these types now have real fields and the blob test never sees them.
  - **C11 name injection**: `n.x`, not `n._anon1.x`. A declared field always wins over an injected name, each name is emitted once, the synthetic `_anonN` never travels upward (it would shadow the enclosing struct's own field), and bitfields are excluded (they're reached via `get_<name>(s)`, not `getproperty`).
  - Three smaller drops fixed in the blob-accessor path while here: **enum members** were silently dropped (`@enum T::U` is a primitive but isn't in `_loadable_primitives` — cost `toml_datum_t` its `type` tag, the field saying which arm is live), **fixed-size arrays** were dropped, and the nested-struct branch required `m_sanitized != m_c_type` so it only ever fired for C++ template spellings — every plainly-named nested struct member (`toml_datum_t toptab;`) was dropped. Union members also got `available_size` 0 (all at offset 0, so the "gap to the next member" is 0); they own the whole aggregate.
  - **Synthetic names must be pre-sanitized.** `_sanitize_c_type_name` collapses `_+`, so `Parent` + `_` + `_anon1` was rewritten to `Parent_anon1` at emission while the dep graph still keyed on the raw spelling — the edge missed, the topological sort emitted the PARENT FIRST, and it fell back to a blob anyway. Caught only by reading the emitted wrapper; the build was green.
  - **Cross-CU dedup**: every CU including the header declares the anonymous aggregate again with its own DIE. mpack_tag_t's union appeared in six → `mpack_tag_t_v` through `_v_6`, five dead types shipped. Structurally identical aggregates (kind + byte_size + ordered member name/offset/bit_size) under the same parent name now share one name.
